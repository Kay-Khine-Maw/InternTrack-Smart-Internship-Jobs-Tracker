# Development Log — 2026-11-17

## Focus

Align the documentation with the application after the profile-match, dialog, logo, and theme changes.

## Decision

Where the documents disagreed, the code is the current behavior. Status stays Implemented. This alignment is not acceptance.

- The displayed profile-match percentage is the deterministic skill and tool count: matched lines divided by matched plus not-met lines. Unknown lines are excluded. Refresh and Recalculate do not change it unless profile skills or tools, or the posting's skill or tool requirements, change. Gemini does not replace that number.
- "Why this percentage" keeps the first comparison sentence and shows the rest as separate sentences. Gemini may rewrite only the later sentences. A successful rewrite is stored in `matchExplanationState` with the input hash. If Gemini fails, the original sentences remain and the panel says smoother wording is unavailable. That failure is not stored as a completed rewrite.
- "How to raise this match" replaces the three chip groups. Cards show only the skill name, ordered required before preferred and shorter rough estimates first. Estimates are not promises and are not printed on the cards. Hover or focus darkens the card and shows a grey underlined See more button. The dialog explains how to learn the skill and lists Gemini http(s) links plus Coursera, Udemy, freeCodeCamp, and LinkedIn Learning search links. Invalid non-http(s) links are dropped. This is not a hiring prediction.
- The shared dialog shell keeps rounded corners on all four sides while scrolling, and tall dialogs keep top padding while scrolled. The skill dialog is wider (`sm:max-w-2xl`), has no card shadow, and its Close button uses the accent button color.
- The logo in the sidebar and on the sign-in page keeps its intrinsic aspect ratio.
- A dashboard dark theme was tried and then removed. The app is light theme only. Intermediate notes in the 2026-11-16 log that describe a Gemini percentage or a dark dashboard are not current behavior.
